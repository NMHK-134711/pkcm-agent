## 1. 환경 세팅 (새 PC에서 한 번)

`.venv`는 **옮기지 않는다.** 4.8GB이고, 안에 이전 PC의 절대경로가 박혀 있고, torch 휠은
어차피 그 PC 드라이버에 맞춰 다시 깔아야 한다.

git에 없는 것은 `data/raw/`뿐이고, **손으로 옮기지 않는다 — 스크립트가 다시 받는다**
(§1b). `data/dex.py`의 `RAW_DIR`가 그걸 읽으므로 없으면 `load_dex()`가 죽는다.

```bash
git clone https://github.com/NMHK-134711/pkcm-agent.git && cd pkcm-agent
```

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -e ".[rl,train,dev]"
```

GPU를 쓸 거면 torch를 CUDA 빌드로 덮어쓴다 (기본 인덱스는 CPU판을 준다):

```bash
.venv/Scripts/python.exe -m pip install --index-url https://download.pytorch.org/whl/cu128 --force-reinstall torch
```

**인덱스는 카드 세대로 고른다.** RTX 50 시리즈(Blackwell, sm_120)는 `cu124` 휠에 커널이
없어서 `torch.cuda.is_available()`이 True인데 연산에서 "no kernel image is available"로
죽는다 — 설치는 성공한 것처럼 보인다. 40 시리즈 이하면 `cu124`도 된다.

확인한 조합: 이전 PC Python 3.13.12 / torch 2.6.0+cu124 (40 시리즈),
현재 PC Python 3.13.15 / torch 2.11.0+cu128 (RTX 5060 Ti, 드라이버 591.86 / CUDA 13.1).

**`python -m venv`에 쓸 인터프리터가 3.11+인지 먼저 볼 것** (`py -0p`). 3.9로 만든 venv는
`pip install -e .`에서 걸러주지 않고 조용히 서 있다가 나중에 터진다.

```bash
winget install --id Python.Python.3.13 -e --scope user
```

**검증:**

```bash
.venv/Scripts/python.exe -m pytest -q
```

**616개 전부 통과해야 한다.** `data/raw/`를 빼먹었으면 여기서 바로 터진다.

wandb를 쓸 거면 새 PC에서 **직접** `wandb login` 할 것. API 키는 이 저장소를 거치지
않는다. 로그인 안 해도 실행은 정상이고 `runs/<name>/history.json`에 남는다.

## 1b. 다른 PC에서 학습만 이어가기

코드와 커밋된 데이터는 git에 있다. **git에 없는 것은 두 종류뿐이고, 둘 다 스크립트로
다시 만든다** -- 하나는 예외로 커밋해뒀다.

```bash
git clone https://github.com/NMHK-134711/pkcm-agent.git && cd pkcm-agent
```

§1의 환경 세팅(파이썬 3.11+, `pip install -e ".[rl,train,dev]"`, GPU면 cu128)을 끝낸 뒤:

```bash
.venv/Scripts/python.exe scripts/fetch_showdown_data.py && .venv/Scripts/python.exe scripts/fetch_champout.py && .venv/Scripts/python.exe scripts/fetch_pokechams.py
```

`scripts/fetch_sprites.py`는 브라우저 UI(`scripts/play_web.py`)를 쓸 때만 필요하다 —
PokeAPI 스프라이트 608장, 2.3MB.

`data/raw/`는 gitignore돼 있고 이 세 스크립트가 다시 받는다. **`load_dex()`가 이것 없이는
죽으므로 첫 단계다.** `fetch_showdown_source.py`는 메커니즘 참고용 TypeScript라 학습에는
필요 없다. `fetch_pkmnchamps.py`는 랭커 아카이브를 받지만, 거기서 뽑은
`data/champions/parties_m_b.json`은 이미 커밋돼 있으므로 팀을 다시 임포트할 때만 필요하다.

**검증:**

```bash
.venv/Scripts/python.exe -m pytest -q
```

그리고 학습을 건다. `runs/imitate8/net.pt`(19MB, 손으로 짠 탐색 상대 52.5%로 동등)는
**커밋돼 있으므로 사전학습을 다시 돌릴 필요가 없다**:

```bash
.venv/Scripts/python.exe -u scripts/train_loop.py --init runs/imitate8/net.pt --resume --iterations 8 --battles 250 --search-iterations 800 --evaluate-every 2 --evaluate-battles 60 --teams ranker --hidden 512 --blocks 4 --out runs/lab --name from-imitate8
```

**`--resume`는 전원이 끊겨도 이어받는다.** 매 iteration 끝에 `runs/<name>/state.pt`가
원자적으로 쓰인다 -- 망 가중치, 옵티마이저 모멘트, 그리고 **리플레이 버퍼**(40,000샘플,
124MB. 자가대전 일곱 회분이라 이것만은 다시 못 만든다). 같은 명령을 다시 치면 끊긴 다음
회차부터 간다. 잃는 것은 그 회차의 진행분(최대 7분)뿐이다.

wandb run id는 **출력 폴더에서 나오므로**, 몇 번을 끊고 재개해도 차트 하나에 이어 붙는다.
`wandb login`은 그 PC에서 직접 할 것. 안 해도 실행은 정상이고 `history.json`에 남는다.

**진행 확인:**

```bash
.venv/Scripts/python.exe scripts/watch_run.py runs/lab
```

**PC 두 대에서 같은 `--out`을 쓰지 말 것.** `state.pt`는 마지막에 쓴 쪽이 이기고, 두 실행이
서로의 버퍼를 덮어쓴다.

## 2. 탐색은 끝났다 — 값을 낸 수정들

시뮬레이터·환경·탐색은 서 있다. 탐색이 `greedy` 상대 **70.0% [61.3, 77.5]** (800 iter).

값을 낸 수정들 (전부 측정 근거 있음):

- **픽 페이즈가 선택되고 있지 않았다** — `_promise`가 `SELECT`를 전부 0점으로 매겨 상한
  24개가 `permutations` 순서대로 잘렸고, **0번·1번 포켓몬으로만 리드할 수 있었다**
- **PUCT가 단위 다른 두 수를 더했다** — `MinMax`(MuZero) 도입
- **탐험 항이 두 개였다** — `exploration` 0.7 → 0.1
- **`trust`가 사전확률만 섞고 리프 가치는 통과시켰다** — 가치망이 프리뷰에서 ±0.99를
  뱉는데 트리 전체를 지배했다. 이제 둘 다 섞고 홀드아웃 오차로 상한이 걸린다
- **`sample_opponent`를 측정 없이 켰다가 되돌렸다** — 직접 대결 40.5%로 패배

**AlphaZero 루프가 막힌 원인은 측정으로 특정됐다:** 탐색의 방문분포가 자기 사전확률을
재생산하고, 망은 그 열화 복사본을 배우고, 갈아끼우면 탐색이 약해진다. §3이 그 뒤 이야기다.

## 3. 어디까지 왔나 — 사전학습과 데이터 층 (2026-08-27)

### 실행 B는 음성이었다

`prior_weight` 0.35는 아무것도 바꾸지 않았다. 8회 완주, 자가대전 2,000판.

| iter | control (`runs/second`, prior 1.5) | 실행 B (`runs/third`, prior 0.35) |
|---|---|---|
| 1 | 16.2% [9.8, 25.8] | 22.8% [14.9, 33.2] |
| 7 | **22.5%** [14.7, 32.8] | **18.8%** [11.7, 28.7] |

**실행 간 잡음이 신뢰구간보다 크다.** iteration 1을 세 번 측정했다: 17.5%, 21.2%, 22.8%.
데이터가 동일한데도 학습 비결정성만으로 5%p가 벌어진다. **40매치 아레나(±10%p)로 두
실행의 한 지점을 비교해서 결론 내지 말 것.** 결정이 걸리면 `scripts/judge.py`로 200매치를
쓴다 (±4.5%p).

### 그래서 모방 학습으로 갔다 (사용자 결정)

정책망을 손으로 짠 사전확률로 먼저 지도학습시킨 뒤 AlphaZero를 돌린다. 갈아껴도 손해가
없어지고 개선분만 쌓인다. `scripts/pretrain.py` → `train_loop.py --init`.

**판정은 아레나 50%다. 손실이 아니다.** 완벽히 베꼈다면 원본과 구분되지 않아야 한다.

일곱 번 돌렸고, 원인이 세 번 갈렸다:

| 실행 | 바꾼 것 | 픽 1등 일치 | 모방 잔차 | 아레나 |
|---|---|---|---|---|
| 1 | 기본 | 2.5% | +0.207 | 27.5% |
| 2 | 픽 데이터 15배 | 5.0% | +0.207 | 26.2% |
| 3 | 등록 6마리에 종족 팩트 | 6.7% | +0.208 | 18.8% |
| 4 | **우리 팀 세팅 인코딩** | 8.3% | +0.210 | 31.2% |
| 5 | 망 4배 + 20에포크 | — | +0.280 | 33.8% |
| 6 | **프리뷰 6×6 매치업 격자** | **35.8%** | **+0.091** | 29.2% (200매치) |
| 7 | **랭커 팀 분포** | — | **+0.036** | 35.0% (40매치) |

배운 것 셋:

1. **입력에 답이 없으면 무엇을 늘려도 안 된다.** 픽 데이터를 15배 줘도 우연을 못 벗어났다.
   프리뷰에서는 `observation.own`이 비어 있어 **우리 팀의 기술·실능치가 인코딩에 없었는데**,
   `_pick_promise`는 그것들의 함수다. 물리형과 특수형 가브리아스가 **바이트 단위로 같은
   관측**을 냈다. 테스트가 양방향으로 지킨다 (우리 세팅은 보이고, 상대 세팅은 안 보인다).
2. **용량이 아니라 일반화였다.** 망을 4배로 키우니 훈련은 바닥에 붙고 홀드아웃은 나빠졌다.
   픽 사전확률은 "내 6마리 × 상대 6마리 매치업의 합"이고, 평평한 MLP는 그 구조를 못 만들어
   조합을 외운다. 원시항(6×6 격자)을 주자 +0.219 → +0.014로 떨어졌다.
3. **손실이 좋아져도 아레나는 안 따라올 수 있다.** 6차가 픽을 거의 완벽히 모방하는데
   아레나는 29.2%였다. 남은 결손은 **배틀 턴**이고, 1등 일치율이 여섯 실행 내내 62~66%에서
   안 움직였다.

### 교체 순위 매기기는 음성이었다 (2026-08-27)

`_promise`는 **모든 교체를 똑같이 0.6으로** 매긴다. 순위가 아니라 순위 거부다. 사전학습된
망으로 배틀 잔차를 쪼개보니 그게 그대로 보였다:

| 상황 | n | 초과 nats | 1등 일치 |
|---|---|---|---|
| 교체만 가능한 턴 | 140 | **+0.000** | **45.7%** |
| 사전확률이 교체를 원할 때 | 153 | +0.015 | 49.0% |
| 사전확률이 기술을 원할 때 | 993 | +0.060 | 82.4% |

**잔차 0에 1등 일치 46%는 균등분포를 완벽히 베낀 모양이다** — argmax가 동점 깨기로
정해진다. 즉 배틀 쪽 1등 불일치의 절반이 측정 잡음이었고, 실질은 기술↔기술 155건이다.

픽에 쓰는 `analysis.matchup`으로 교체를 순위 매기게 고쳤다 (평균은 `SWITCH_PROMISE`에
고정해서 기술/교체 균형은 안 건드림). 직접 대결 **51.0% [46.1, 55.9]**, 400게임으로도
구분 안 됨. `SearchConfig.switch_matchup` 기본 0으로 되돌렸고 코드는 남겼다.

**논증이 좋았고 측정이 아니라고 했다.** `sample_opponent` 때와 같은 모양이다.

### 믿음 갱신이 통했다 (2026-08-27) — 사전확률 이후 최대 이득

**`determinize`가 상대의 숨은 필드를 전부 균등하게 뽑고 있었다.** 기술은 그 종족이 배울 수
있는 60개(중앙값)에서, 도구는 **147종 전체**에서, 특성·성격도 균등하게. 관측과 모순되지는
않지만 **실제 세팅과 전혀 닮지 않았다** — 랭커 120슬롯이 쓰는 도구는 29종이고 그중 넷이
절반을 차지한다. 탐색은 예산을 "아무도 안 데려오는 상대"에 대한 계획에 쓰고 있었다.

그리고 더 나쁜 것: **본 것이 아무것도 안 좁혔다.** 지진이 나가는 걸 봐도 나머지 셋을 어차피
60개에서 다시 뽑으니 믿음이 그대로였다.

`pkcm/envs/belief.py`가 **세팅을 통째로** 뽑는다 — 랭커 풀에서, 지금까지 본 기술을 전부
포함하고 확인된 도구·특성이 맞는 것만. 일관된 세팅이 나오고(구애스카프가 그걸 원하는
노력치와 함께 온다), 관측이 실제로 후보를 줄인다. 풀에 없는 종족(235 중 42종만 있다)은
기존 동작 그대로다.

**직접 대결 68.6% [63.9, 73.0], 395게임.** 사전확률 도입(45.8% → 66.4%) 이후 처음으로
구분되게 강해진 변경이고, **망이 전혀 필요 없었다.**

이 방향은 [PokeAgent Challenge](https://arxiv.org/abs/2603.15563)와 그 주력 베이스라인
[Metamon](https://arxiv.org/abs/2504.04395)이 가리킨 것이다. Metamon은 탐색을 버리고
**궤적에서 상대의 팀과 성향을 추론하는** 시퀀스 모델로 사다리 상위 10%에 갔다. 우리 관측은
매 턴 독립이고 역사가 없었는데, 그 아이디어를 탐색의 믿음 쪽에 넣은 것이 이거다.

**남은 확장:** 지금은 세팅 풀에 대한 균등 추출이다. 관측 역사로 가중을 주는 것(스카프를
드러냈으면 스카프 세팅에 무게), 그리고 상대가 6마리 중 어느 3마리를 데려왔을지에
`_pick_promise`를 쓰는 것이 다음 단계다.

### 한 턴짜리 에이전트에게는 상대 정보가 무가치하다 (2026-08-27)

`pkcm/search/scripted.py`가 `GreedyPolicy`의 고정 계수를 파라미터로 푼 여섯 성격이다.
`worth = ko_chance * 10 + percent.low / 100`의 그 **10이 이미 극단적 도박 성향**이었다 —
확정 60% 데미지와 60% 난수 원킬 사이에서 항상 후자를 고른다. 계수를 내리면 다른 사람이 된다.

초당 39판, 탐색 자가대전의 80배. 라운드로빈에서 성격마다 세기가 다르다
(reckless 40승 ~ defensive 15승). **약한 성격이 값이 없는 게 아니라 다른 상태를 보여주는
것이 값이다** — 궤적 다양성과 리그 구성원이 용도다.

**행동 복제 대상으로는 절대 쓰지 않는다.** 특히 `omniscient` 변형은 상대를 정확히 읽으므로,
그걸 클론하면 망이 못 보는 정보의 함수를 예측하라는 요구가 된다 — 픽 페이즈가 실패한 것과
같은 모양이다. 스파링 상대와 궤적 생성기로만 쓴다.

**그 전지 변형으로 정보의 가치를 쟀더니 0이었다:**

| 성격 | 전지 쪽 승률 (240게임) |
|---|---|
| greedy | 47.7% [41.5, 54.0] |
| safe | 46.9% [40.6, 53.2] |
| gambler | 46.7% [40.5, 53.0] |

**한 턴짜리 에이전트는 상대 정보를 쓸 데가 없다.** 안 드러난 기술을 알아도 다음 턴을 안
보니 행동이 안 바뀐다. 그리고 이것이 믿음 갱신이 왜 +18.6%p였는지를 설명한다 —
**정보의 값은 아는 데 있는 게 아니라 그걸로 앞을 내다보는 데 있다.**

따라서 믿음 모델링의 진짜 천장은 **탐색에 전지 시야를 주고 재는 것**이다. 아직 안 쟀다.

### 남은 것

- **배틀 턴 모방이 62~66%에 고정돼 있다.** 픽에 들었던 처방(원시항을 주는 것)을 배틀 항
  (`위력 × 상성 × 자속`)에도 시도해볼 만하다
- 아레나가 50%에 닿으면 `train_loop.py --init runs/imitateN/net.pt`로 AlphaZero를 돌린다
- 회피 클로즈는 **근거 없이 남아 있다** (`ruleset_m_b.json`에 명시)
- `party_samples/메가아쿠스타_비파티.txt`가 없어 `test_party_samples.py`가 실패한다 (hk 작업)

### 만들어뒀지만 아직 안 켠 것

`TrainConfig.search_value_weight` — 가치 타깃을 승패 대신 탐색의 루트 값과 섞는다.
**기본 0.** 프리뷰에서 팀 조합이 반복되지 않아 망이 "몇 번 배틀인지" 외울 수 있다.
검증은 항상 진짜 결과로 채점하므로 켜보고 아레나로 판정하면 된다.

## 4. 이 프로젝트에서 반복해서 옳았던 것

전문은 [HANDOFF.md](HANDOFF.md)의 "밟기 쉬운 함정". 특히:

- **`greedy` 상대 승률 두 개를 비교하지 말 것.** exploration 0.3과 0.7이 greedy 상대
  75.0%와 68.8%였는데 서로 붙이니 50.3%였다. `arena.py --exploration-b`, `--prior-b`,
  `--ablate`로 **직접** 붙인다
- **점추정을 진전으로 읽지 말 것.** 이 프로젝트는 세 번 속았다
- **측정 없이 기본값을 바꾸지 말 것.** `sample_opponent`가 그렇게 들어갔다가 되돌아갔다
- **"등록만 하고 아무도 안 읽는" 코드가 최다 빈출 버그다.** 실패하지 않아서 안 보인다.
  `_promise`가 `SELECT`를 0점으로 매기던 것도 같은 모양이다
- **학습 손실은 홀드아웃 없이 읽지 말 것**
- **계산기는 `Observation`만 받는다.** `BattleState`를 받는 순간 독심술이 정책으로 샌다
- **룰의 출처는 챔피언스 소스뿐이다.** Showdown은 메커니즘 참고용이고 자체 룰셋을 돌린다.
  수면·OHKO 클로즈 둘 다 게임에 없었고, 우리는 그걸 두 겹으로 틀리게 모델링하고 있었다
  (버섯포자는 "막힌 기술"이 아니라 **없는 기술**이었다)
- **이름을 옮기지 말고 조회할 것.** `data/champions/names.json`에 종족·기술·도구·특성이
  다 있다. 이 세션에서 영문 id를 보고 한국어를 지어낸 게 세 번이고 세 번 다 틀렸다
- **출처가 여럿이면 서열을 정할 것.** ROM > 포케챔스·pkmnchamps > Showdown. 서열이
  없으면 "어느 쪽이 맞나"를 매번 다시 논쟁하게 된다
- **원본 데이터에 비활성 항목이 섞여 있는지 볼 것.** `waza_learn.json`이 그랬고, 필터
  없이 읽어서 "우리 표가 252칸 모자라다"고 정반대로 보고했다. 필터를 거니 **0칸 부족,
  254칸 과다**였다

## 5. 진행 중이던 측정 (참고)

`arena.py` 직접 대결, 전부 200판 · 팀 미러링 · 양쪽 자리:

| | |
|---|---|
| `sample_opponent` 끈 쪽 | **59.5% [52.6, 66.1]** 구분됨 → 껐다 |
| `normalize_value` 끈 쪽 | 54.3% [47.3, 61.0] 구분 안 됨 → 타깃 품질 때문에 켜둠 |
| exploration 0.1 vs 0.7 | 53.8% [46.8, 60.6] 구분 안 됨 |
| **`switch_matchup` 0.4 vs 0.0** | **51.0% [46.1, 55.9]** 구분 안 됨 (400게임, 랭커 팀) |
| **`belief` 켬 vs 끔** | **68.6% [63.9, 73.0]** **구분됨 — 켰다** (395게임, 랭커 팀) |
| prior_weight 0.75 vs 1.5 | 53.5% [46.6, 60.3] 구분 안 됨 |
| prior_weight 0.35 vs 1.5 | 52.0% [45.1, 58.8] 구분 안 됨 |
| prior_weight 0.15 vs 1.5 | 49.0% [42.2, 55.9] 구분 안 됨 |
| prior_weight 0.0 vs 1.5 | 44.5% [37.8, 51.4] 구분 안 됨 (열세 쪽으로 기움) |

`prior_weight`는 한 줄도 단독으로는 구분이 안 되지만, 네 번이 순서대로 내려가는 건
경향이다. 바닥이 0.35 근처. **0은 측정과 무관하게 선택지가 아니다** — 정책망이 곧
사전확률이라, 0이면 망이 탐색에 아무 영향도 못 준다.
