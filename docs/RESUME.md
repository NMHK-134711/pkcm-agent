## 1. 환경 세팅 (새 PC에서 한 번)

`.venv`는 **옮기지 않는다.** 4.8GB이고, 안에 이전 PC의 절대경로가 박혀 있고, torch 휠은
어차피 그 PC 드라이버에 맞춰 다시 깔아야 한다.

git에 없는데 필요한 건 두 개뿐이다:

| 폴더 | 크기 | |
|---|---|---|
| `data/raw/` | 7.1MB | **필수** — `data/dex.py`의 `RAW_DIR`가 읽는다. 없으면 `load_dex()`가 죽는다 |
| `runs/second/` | 5MB | control 실행의 체크포인트·기록. 비교 기준 (필수 아님) |

```bash
git clone https://github.com/NMHK-134711/pkcm-agent.git
```

압축 풀어서 `data/raw/`를 저장소 안에 넣고:

```bash
python -m venv .venv
```

```bash

```

GPU를 쓸 거면 torch를 CUDA 빌드로 덮어쓴다 (기본 인덱스는 CPU판을 준다):

```bash

```

이전 PC 기준 Python 3.13.12 / torch 2.6.0+cu124. 드라이버가 낮으면 `cu121`.

**검증:**

```bash

```

**574개 전부 통과해야 한다.** `data/raw/`를 빼먹었으면 여기서 바로 터진다.

wandb를 쓸 거면 새 PC에서 **직접** `wandb login` 할 것. API 키는 이 저장소를 거치지

## 2. 어디까지 왔나 (2026-08-27 기준)

시뮬레이터·환경·탐색은 끝났다. **막혀 있던 건 AlphaZero 루프였고, 오늘 원인을 찾아
고쳤지만 그 수정이 실제로 효과가 있는지는 아직 측정 안 됐다.**

### 오늘 확정된 것

탐색이 `greedy` 상대 **70.0% [61.3, 77.5]** (800 iter). 이전 기록 65.0%와 구간이 겹치므로
"최소한 같은 세기, 학습 타깃은 훨씬 좋아짐"이 정확한 표현이다.

고친 것들 (전부 측정 근거 있음, `git log` 참고):

- **픽 페이즈가 선택되고 있지 않았다** — `_promise`가 `SELECT`를 전부 0점으로 매겨서,
  싱글 120개 중 상한 24개가 `permutations` 순서대로 잘렸다. **0번·1번 포켓몬으로만
  리드할 수 있었다.** `_pick_promise`가 채운다
- **`_pick_promise`가 상대 실제 기술·실능치를 읽고 있었다** (프리뷰에 안 보이는 정보).
  종족 + `analysis.midpoint`만 읽도록 수정, 테스트 2개가 지킨다
- **PUCT가 단위 다른 두 수를 더했다** — `MinMax`(MuZero) 도입
- **탐험 항이 두 개였다** — `exploration` 0.7 → 0.1
- **`sample_opponent`를 측정 없이 켰다가 되돌렸다** — 직접 대결 40.5%로 패배
- **`trust`가 사전확률만 섞고 리프 가치는 통과시켰다** — 가치망이 프리뷰에서 ±0.99를
  뱉는데 트리 전체를 지배했다. 이제 둘 다 섞고, `trust`는 홀드아웃 오차로 상한이 걸린다
- **홀드아웃 검증** — 배틀 단위 분할. 첫 실행이 train mae 0.032 / 미본 배틀 0.771이었다
  (상수 0이 정확히 1.0)

### 핵심 원인과 그 수정

**탐색의 방문분포가 자기 사전확률을 재생산하고 있었다.** AlphaZero의 엔진 전체가
"탐색이 사전확률을 이긴다 → 망이 그 차이를 배운다"인데 그 차이가 없었다. `prior_weight`
1.5에서 +0.037 nats, 사전확률 1등을 65% 그대로 골랐다.

원인은 보정 문제였다. AlphaZero의 c_puct는 Q가 [-1, 1]인 걸 가정하는데 min-max는 [0, 1]로
만든다 — 1.5가 저쪽 3.0처럼 당겼다. **`prior_weight` 0.35로 낮추니 세 구간 전부에서
탐색이 사전확률보다 뾰족해졌다:**

| | 1.5 (이전) | 0.35 (현재) |
|---|---|---|
| 프리뷰 | 2.992 → 3.017 (더 평평) | 2.992 → **2.917** |
| 턴 6 | 1.265 → 1.204 | 1.265 → **1.056** |
| 턴 12 | 1.230 → 1.264 (더 평평) | 1.230 → **1.073** |

세기 손해는 없다 (1.5 상대 200판 직접 대결 52.0% [45.1, 58.8], 구분 안 됨).

## 3. 바로 다음에 할 일

**학습 실행 B를 돌리고 control과 비교한다.** 이전 PC에서 iteration 0까지만 돌고 중단됐다.

```bash
.venv/Scripts/python.exe scripts/train_loop.py --iterations 8 --battles 250 --search-iterations 800 --evaluate-every 2 --evaluate-battles 40 --out runs/third --name prior-035
```

`runs/third/`가 이미 있으면 지우고 시작할 것 (1 iteration짜리 찌꺼기).

### 비교 대상 — control (`runs/second`, 8회 완주)

| iter | 홀드아웃 value mae | 아레나 vs 손으로 짠 탐색 |
|---|---|---|
| 1 | 0.643 | 16.2% [9.8, 25.8] |
| 3 | 0.314 | 19.0% [11.9, 29.0] |
| 5 | 0.192 | 20.0% [12.7, 30.0] |
| 7 | 0.234 | 22.5% |

**성공 판정:** 실행 B가 같은 iteration에서 control보다 **확실히 빠르게** 올라가고 50%에
도달해야 한다. control은 8회, 자가대전 약 2,000판을 쓰고도 계속 "구분되게 열세"였다.

**주의:** 뾰족해졌다는 건 루프에 따라갈 기울기가 생겼다는 뜻이지, 그 기울기가 좋은 데로
간다는 보장이 아니다. **아레나 숫자만 답을 안다.** 손실은 망이 주어진 걸 맞추기 때문에
어차피 내려간다.

### 실행 B가 control과 비슷하면 — 미해결 갈림길

이건 **사용자 결정이 필요한 설계 분기**다. 임의로 고르지 말 것.

1. **정책망을 손으로 짠 사전확률로 먼저 모방 학습** → 그 다음 AlphaZero. 갈아껴도 손해가
   없어지고 개선분만 쌓인다. 측정된 원인을 직접 겨냥하는 유일한 선택지 (권장)
2. 탐색 자체를 사전확률보다 확실히 강하게 (iteration 증량, 리프 개선) — 데이터가 느려진다
3. AlphaZero 틀을 버리고 탐색과 손으로 짠 사전확률을 직접 개선

### 만들어뒀지만 아직 안 켠 것

`TrainConfig.search_value_weight` — 가치 타깃을 "누가 이겼나" 대신 탐색의 루트 값과 섞는다.
**기본 0 (꺼짐).** 프리뷰에서는 관측에 양쪽 등록 6마리가 다 들어가고 팀이 무작위라 팀 조합이
절대 반복되지 않는다. 즉 **망이 "이게 몇 번 배틀인지" 알아보고 결과를 외울 수 있고, 데이터를
더 준다고 해결되지 않는다.** 검증은 항상 진짜 결과로 채점하므로(테스트가 지킨다) 켜보고
아레나로 판정하면 된다.

## 4. 이 프로젝트에서 반복해서 옳았던 것

전문은 [HANDOFF.md](HANDOFF.md)의 "밟기 쉬운 함정". 특히:

- **`greedy` 상대 승률 두 개를 비교하지 말 것.** exploration 0.3과 0.7이 greedy 상대
  75.0%와 68.8%였는데 서로 붙이니 50.3%였다. `arena.py --exploration-b`, `--prior-b`,
  `--ablate`로 **직접** 붙인다
- **점추정을 진전으로 읽지 말 것.** 이 프로젝트는 세 번 속았다
- **측정 없이 기본값을 바꾸지 말 것.** `sample_opponent`가 그렇게 들어갔다가 되돌아갔다
- **"등록만 하고 아무도 안 읽는" 코드가 최다 빈출 버그다.** 실패하지 않아서 안 보인다.
  `_promise`가 `SELECT`를 0점으로 매기던 것도 같은 모양이다
- **학습 손실은 홀드아웃 없이 읽지 말 것**
- **계산기는 `Observation`만 받는다.** `BattleState`를 받는 순간 독심술이 정책으로 샌다

사전확률이라, 0이면 망이 탐색에 아무 영향도 못 준다.
