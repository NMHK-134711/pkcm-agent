### 왜 `move_support`로는 안 되는가

**그게 오늘 다섯 번 틀렸다.** `move_support`는 데이터의 *모양*으로 답한다 — 엔진이
이름을 아는 필드가 하나라도 있으면 "지원됨"이다. 기습이 실패 조건 없이 통과한 것도,
배턴터치가 데미지 없는 유턴으로 통과한 것도 같은 이유다. 그래서 하네스는 다른 질문을
한다: **판을 깔고, 실제로 쓰고, 무엇이 일어났는지 본다.**

### 검사를 쓸 때 걸리는 함정 — 오늘 12개 중 절반이 여기서 헛돌았다

내 시나리오가 틀려서 엔진이 정상인데 실패로 나온 경우들이다. 그대로 반복하지 말 것.

| 함정 | 실제로 일어난 일 |
|---|---|
| 타입 면역 | 팬텀에게 리벤지(격투) → `immune`. 블리스에게 섀도볼(고스트) → `immune` |
| 대조군이 판을 바꿈 | 날개쉬기는 **비행 타입을 벗긴다** → 격투 배수가 1배에서 2배로. 철벽은 상대 방어를 올려 위력 비교를 망가뜨린다 |
| 특성이 결과를 흉내냄 | 불꽃숭이의 **위협**이 공격 −1을 걸어서, 아무것도 안 하는 막말내뱉기가 작동하는 것처럼 보였다 |
| 스피드 | 벽을 깔기 전에 상대가 때렸다. 벽 없는 상태를 두 번 잰 셈 |
| 방어 | 대조군이 `protect`를 눌러 측정 대상이 아예 안 닿았다 |
| HP 뺄셈 | 목숨걸기가 정상인데, 같은 턴에 상대가 날개쉬기로 회복해서 "덜 들어갔다"로 읽혔다 |
| 사용자가 먼저 죽음 | 죽기살기·리벤지 검사가 사용자가 쓰러진 뒤라 측정이 0이었다 |

**그래서 검사는 실패할 때 본 값을 반드시 같이 찍는다.** 못 믿을 통과보다 읽을 수
있는 실패가 낫다. 새 검사를 쓸 때도 이 규칙을 지킬 것.

### 자동 조사는 출발점일 뿐이다

`raw`의 키/값 중 엔진 소스에 문자열이 없는 것을 훑으면 후보가 나오는데, **거짓
양성이 절반이다** — 비바라기·소원·저주·섀도다이브는 그렇게 걸렸지만 전부 정상이었다.
반대로 실제 버그 다섯 개 중 리벤지는 그 조사에 안 걸렸다(키가 아니라 표 등록 누락).
조사로 후보를 좁히되, **판정은 반드시 실행으로** 할 것.

### `1911a4f`이 고친 다섯

- **배턴터치** — `selfSwitch`가 `True`가 아니라 `'copyvolatile'`인데 truthy로만 읽어
  유턴 경로로 갔다. 랭크가 교체와 함께 지워졌다. 필드 **10파티**가 들고 있다
- **꼬리자르기** — 대타출동을 만들자마자 `return`해서 교체 분기에 못 갔다. 3파티
- **막말내뱉기** — 하락이 쇼다운의 `onHit`에 있어 `boosts` 필드가 없다. 아무것도
  안 했다. 3파티
- **절대영도** — `ohko`가 가위자르기는 `True`, 절대영도는 **타입 이름 `'Ice'`**.
  플래그로 읽어 얼음타입을 일격사시켰다. 3파티
- **리벤지** — `VARIABLE_POWER` 표에 누락. 쌍둥이인 눈사태는 처음부터 있었다

그리고 공통 원인 하나: **공식을 건너뛰는 데미지가 `hurtthisturn` 원장에 안 실렸다**
(지구던지기·나이트헤드·용의분노·소닉붐·거대이빨). 카운터가 지구던지기에 "실패"로
답했고, 눈사태가 그걸 맞고도 위력 60이었다.

## 3. 왜 지금 재면 안 되는가

hk의 목표는 "웬만한 파티에 대응방법이 있는, 저점이 높은 파티"다. 어제 라운드로빈에서
**파티의 변화기 비중과 승률의 상관이 −0.457**로 단조롭게 나왔다(변화기 3칸 56.8% →
14칸 43.5%). 이게 "변화기 파티가 실제로 약하다"인지 "우리 쪽이 변화기를 못 다룬다"인지
갈라야 하는데, 오늘 그 원인이 최소 셋으로 쪼개졌다.

1. **사전확률** — 고쳤다. 50파티 재측정에서 변화기 많은 파티가 적은 파티 대비
   +3.5%p 올라갔다(t≈2.1, 시사적이지 확립은 아님). 전체 기울기는 −0.50 → −0.47로
   거의 안 움직였다. **원인의 일부지 주범이 아니다**
2. **기술 미구현** — 배턴터치·막말내뱉기·꼬리자르기가 아예 안 돌았다. 그리고 이건
   정확히 변화기 많은 파티에 들어간다. 고쳤지만 **나머지 488종은 안 봤다**
3. **말단 평가** — 물량 세기는 이 탐색이 도달하는 2.8턴 안에서 벽·설치기·축적을
   점수로 셀 수 없다. `evaluate.py`가 스스로 적어놓은 한계다

**2가 끝나기 전에는 3을 잴 수 없다.** 그래서 전수 검사가 먼저다.

## 5. 명령 모음

```bash
# 기술 실측 검사
python scripts/mechanic_check.py

# 253파티 라운드로빈 (개인PC 19워커 분당 40대진, 랩실 10워커 분당 10대진)
python scripts/tournament.py --parties data/champions/parties_field.json \
    --repeats 2 --search-iterations 800 --preview-iterations 3200 \
    --workers <물리 코어> --out runs/field_rr_800_v2.json   # 랩실은 뒤에 --reverse
```

두 기계가 스케줄 양 끝에서 마주보고 돌린다. `--reverse` 없이 둘이 같이 돌리면
통째로 중복 계산한다. `runs/field_rr_*.jsonl`은 `merge=union`이라 pull이 자동 병합한다.
`--parties`·`--repeats`·`--search-iterations`·`--preview-iterations`는 양쪽이 같아야
하고 `--workers`만 기계에 맞춘다.
